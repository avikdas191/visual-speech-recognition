Rebuild workspace
=================

Intermediate and generated data for the lip reading dataset rebuild.
Not part of the git repository - too large, and regenerable from the
notebooks in lip_codebase_clean/src/.

Source videos live in the archive at
/mnt/d/lip_codebase/Data for lip reading model/Videos of 10 selected
words named/ and are never modified.


NAMING CONVENTION
-----------------
Numbered folders 01-06 follow the pipeline in order. Where a variant
diverges from the main chain, it takes the number at which it diverges
plus a letter suffix:

  (none)  main chain: RGB, 224x224, original 16 augmentation types,
          48 augmented training sets
  b       aspect-ratio preserved, RGB, 224x267
  g       grayscale, single channel
  t       temporal augmentation swaps
  p       photometric/geometric augmentation swaps
  v       original types, 96 augmented training sets
  f       original types, 96 sets, full 16-type evaluation coverage
  ft      temporal swaps, 96 sets, full coverage
  fp      photogeo swaps, 96 sets, full coverage
  h       original types, 144 augmented training sets
  i       original types, 192 sets
  j       original types, 288 sets

Train is 42 real recordings plus augmented sets. Validation and test
are 9 real recordings plus augmented sets. The real recordings are
identical across every variant.


WHERE THE VARIANTS DIVERGE
--------------------------
ASPECT (b) - diverges at the resize step only. The 672x800 grid is
scaled by 0.333 in both directions to 224x267, preserving each lip
crop's 1.40 aspect ratio. The main chain forces 224x224, stretching
each crop horizontally by 19%.

GRAYSCALE (g) - diverges at the crop stage, so that augmentation runs
on grayscale as a genuine grayscale pipeline would. Applying colour
augmentations and then discarding colour would test something that
does not exist. Two augmentation changes: RGBShift becomes
RandomGamma(60,140), and ProcessCroppedImage applies CLAHE directly to
the single channel rather than via LAB conversion.

TEMPORAL (t, ft) - the four weakest original types by measured pixel
change (TemporalShift 0.00, OpticalDistortion 2.59, GaussianBlur 2.49,
Downsample 2.08) are replaced by FrameMorph, DropRefill, SmoothDrift
and CoarseDropout. The first three operate across all 60 frames rather
than per frame - nothing in the original set touched temporal
structure.

PHOTOGEO (p, fp) - the same four types replaced instead by
RandomShadow, CLAHEVarying, GridDistortion and ElasticTransform.

VOLUME (v, h, i, j) - original 16 types, more augmented sets:
96, 144, 192 and 288 for training. Evaluation stays at 11 augmented
sets so the figures remain comparable.

FULL COVERAGE (f, ft, fp) - 16 augmented sets in validation and test
instead of 11, giving one of every augmentation type. With only 11
slots, five types are always absent from evaluation. Figures from
these three are not comparable to the others.


AUGMENTATION PLAN ASSIGNMENT
----------------------------
Two algorithms build the plans.

The original shuffles the type list and retries until no recording
session receives the same type twice. This works up to six uses per
type.

At nine or more uses (h, i, j) most sessions must receive seven or
more distinct types from sixteen, and random shuffling cannot satisfy
this - five hundred attempts failed. Those plans use a constructive
method that deals types out in rounds, choosing the session with the
most remaining slots that has not yet received that type.

Dispatch is on uses per type: six or fewer takes the original path, so
the earlier plans regenerate identically.

LOGS
----
  frame_extraction_log.csv            per video: source frames, padding
  crop_detection_log.csv              per video: detection successes
  augmentation_candidate_measurement_log.csv
                                      pixel change and stochasticity
                                      for every candidate type
  augmentation_plan_*_log.csv         nine plans: which session and
                                      type produced each augmented set
  augmentation_generated_*_log.csv    actual output per plan
  grid_assembly_log.csv               and _gray_ variant
  resize_log.csv                      and _aspect_preserved_ variant
  final_image_mapping_log.csv         every final image to its source
  final_image_mapping_*_log.csv       per variant
  training_history_log.csv            baseline training curve
  class_labels_rebuilt.json

final_image_mapping_log.csv is the important one. It records which
recording session produced each image in the finished dataset. The
aspect and grayscale variants reuse it unchanged, so image 001.png in
Test/bat comes from the same session in all three.


REGENERATING
------------
  src/data_prep/generate_rebuilt_dataset.ipynb
      main RGB chain, stages 01-06

  src/data_prep/generate_aspect_and_grayscale_datasets.ipynb
      aspect and grayscale variants

  src/data_prep/augmentation_candidate_measurement.ipynb
      measures candidate augmentation types

  src/data_prep/generate_augmentation_variant_datasets.ipynb
      the nine augmentation variants

Every random operation is seeded. Split seed 4, augmentation seed 101
for the main chain, 201-209 for the variants.


DISK
----
Roughly 800,000 augmented frames and 18,000 grid images across all
variants. If space is needed, the 03* and 04* intermediate folders can
be deleted - the 06* datasets are what training reads, and the
intermediates regenerate from the plans.
